# M1 · 文档规范（归属判定 + 任务路由）

|        |                                                           |
| ------ | --------------------------------------------------------- |
| ID     | `M1`                                                      |
| 类型   | 规格（元规范）                                            |
| 状态   | 稳定                                                      |
| 更新   | 2026-10-15                                                |
| 何时读 | **新建 / 搬移文档**时；**开新任务、不确定该读哪些文档**时 |
| 规模   | ~1.5k token                                               |

## TL;DR

- 路径只登记在 `AGENTS.md` §2 一处；文档之间**只写 ID**。
- 判定归属只问一句：**机制**（怎么连库 / 怎么存 / 怎么发信）→ 对应 `packages/*`；**语义**（业务功能怎么进行）→ `apps/*` + `packages/api`；**跨模块** → 根 `docs/`。
- 状态就地更新、从不搬家；未决问题只进 `S2`；ADR 只增不改。

## 1. 文档归属判定（新增文档放哪）

按顺序自问，命中即停：

| 问题                                                                      | 放哪                                                                                                               |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 这是**怎么连库 / 怎么存对象 / 怎么发信 / 怎么鉴权**这类可复用的**机制**？ | 对应机制包：`packages/<pkg>/README.md`（门面）+ `packages/<pkg>/docs/*.md`（细节）。**机制文档不许出现业务名词。** |
| 这是**某个业务功能**怎么进行（上传、文件管理、分享、同步…）？             | `apps/*` 或 `packages/api`：README + `docs/`，垂直落地到对应 router / 页面                                         |
| 是「这个模块在做什么」的**可视化图**？                                    | 该模块 `docs/<slug>.html`；ID = 规格 ID + `-V`                                                                     |
| 是**生成物**（OpenAPI spec 等），可再生？                                 | `docs/reference/`，勿手工编辑                                                                                      |
| **影响多个模块 / 全项目**？                                               | 根 `docs/*.md`（如 `G1`、`A1`、`A6`）                                                                              |
| 是**决策**（选了什么、为什么）？                                          | `docs/decisions/NNNN-<slug>.md`，只增不改                                                                          |
| 是**长期计划**且**尚无归属模块**？                                        | `docs/plans/*.md`                                                                                                  |
| 是**当前阶段状态·概览**？                                                 | 根 `STATUS.md`（`S1`）                                                                                             |
| 是**当前阶段状态·某模块细节**？                                           | `packages                                                                                                          | apps/<模块>/status.md`（按需建立、随任务生灭） |
| 是**未决问题**？                                                          | 根 `OPEN-QUESTIONS.md`（`S2`）                                                                                     |
| 是**里程碑与排期**（不含状态）？                                          | `docs/roadmap.md`（`RM`）                                                                                          |

## 2. 机制 vs 语义（核心判据）

落点只问一句：

- 「**怎么连 PostgreSQL / 怎么读写对象存储 / 怎么发 SMTP**」= **机制** → `packages/db`、`packages/storage`、`packages/mail`
- 「**上传怎么进行 / 目录怎么列 / 分享怎么授权**」= **语义** → `apps/*` + `packages/api`

判据不稳定时，看它是否**可脱离业务复用**：能复用的技术能力 = 机制。

**依赖方向（硬规则，见 `A1` §2）**：`apps/* → packages/* → packages/config`，只能向下，禁止反向。文档归属也服从该方向——机制文档不引用语义文档，除非用 ID 泛指。

## 3. ID 前缀约定

**看 ID 就知道它大概是什么、属于谁**：

| 前缀        | 含义                                | 前缀           | 含义                       |
| ----------- | ----------------------------------- | -------------- | -------------------------- |
| `S1` / `S2` | 状态概览 / 未决问题                 | `P1–Pn` / `PT` | 供应商 / 插件文档 / 其模板 |
| `G1`        | 目标与技术路线                      | `X1–Xn`        | 调研（一次性、会过时）     |
| `A1–An`     | 架构与契约（跨模块或归属某模块）    | `D0–Dn`        | 决策 ADR（只增不改）       |
| `R1–Rn`     | 运行时（配置 / 路由 / 观测 / 限流） | `RM`           | 里程碑排期（**不含状态**） |
| `Q1–Qn`     | 质量（测试 / 评测 / 安全）          | `GUI`          | 某期计划                   |
| `M1`        | 文档规范（本文件）                  | `T0`           | 文档模板                   |
| `-V` 后缀   | 对应规格的可视化图                  | `⬜`           | 文件不存在（待建）         |

模块内部文档也可用 `crate:<pkg>#<slug>` 形式，避免挤占全局 ID 空间。

## 4. 任务路由表（任务 → 该读哪些文档）

| 任务                          | 加载                                        |
| ----------------------------- | ------------------------------------------- |
| 现在做什么 / 下一步           | `S1` → 命中任务后进它链接的模块 `status.md` |
| 整体排期 / 完成标准           | `RM`                                        |
| 等用户拍板的事                | `S2`                                        |
| 新建 / 改模块、调目录结构     | `A1` → 该模块 `README.md`                   |
| 改表结构 / 加字段             | `A2` → `packages/db/README.md`              |
| 加 / 改接口、对齐前端         | `A3` → `packages/api/README.md`             |
| 加存储驱动、改取流 / 加密     | `A4` → `packages/storage/README.md`         |
| 加页面、改布局 / 样式         | `A5` → `apps/web/README.md`                 |
| 实现上传 / 分享 / 同步等功能  | `A6`                                        |
| 争论「要不要自研 / 先做哪个」 | `G1`                                        |
| 「这段代码该放哪」            | 本文 §2（机制 vs 语义）                     |
| 推翻某个决定                  | 对应 `D*` → 写**新** ADR（旧的不改）        |

## 5. AGENTS.md 地图（§2）的写法

- 地图是**一张表**，人和 agent 共用。每条含：`ID | 标题 | 路径 | 何时读 | 规模 | 状态`。
- **按来源分组**：状态与排期 / 跨模块规格与契约 / 各模块门面 / 决策记录 / 计划与调研。
- **只列已存在的文件加链接**；`⬜`（待建）的**保持纯文本**，避免死链。
- 规模用 `~Xk token`（≈KB × 350，中文），供读者估算成本。
- 地图**只登记标题与路径**，不复制文档内容。
- 新文档写完**必须**回填地图状态列（`⬜ → ✅`）——这是「写完了」的一部分。
