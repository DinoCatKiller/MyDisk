# ADR-0006：文档跟代码走（本体系的组织方式）

|        |                                                     |
| ------ | --------------------------------------------------- |
| ID     | `D6`                                                |
| 类型   | 决策（**只增不改**）                                |
| 状态   | 已接受                                              |
| 更新   | 2026-10-15                                          |
| 何时读 | 想改文档组织方式、想把所有文档塞回一个大 `docs/` 时 |
| 规模   | ~0.6k token                                         |

## 背景

本仓库此前把设计文档集中堆在一个 `docs/` 目录（份数少、彼此混在一起），与代码分离。随着 P2+ 各功能分模块落地，集中式文档会迅速过期（改代码的人不会去远处更新文档，且它长期停留在"待评审 v1.0"而 P0/P1 实已交付）。

## 备选方案

| 方案      | 说明                                                                                                                                                  | 优点                                 | 缺点                                     |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | ---------------------------------------- |
| A（选中） | **文档跟代码走**：机制文档进 `packages/*`、语义进 `apps/*`/`packages/api`；跨模块才进根 `docs/`。配 **单一大地图**（`AGENTS.md` §2）+ **引用只写 ID** | 谁改代码谁改文档；搬文件只改地图一行 | 初次搭建需要一次搬迁                     |
| B         | 单一 wiki（外部）                                                                                                                                     | 集中                                 | 与代码彻底分离，漂移最快                 |
| C（现状） | 全部堆在 `docs/`，无地图                                                                                                                              | 零成本                               | 无入口、无归属，读者不知道从哪读、该读哪 |

## 决定

**采用 A：文档按归属就地放置，路径只在 `AGENTS.md` §2 登记一次，文档之间只写 ID 互引；状态分层且不搬家（概览 `S1` / 模块 `status.md` / 排期 `RM`）；未决问题唯一来源 `S2`；ADR 只增不改。**

**最关键的理由：文档腐烂的根因是"文档离代码太远、且没有唯一入口" —— 把文档放到代码旁边、把路径收拢到一张地图，才能让改代码的人顺手改文档。**

刻意收窄：**不建**空文件（规划中的只在地图标 `⬜`）；**不设** `done/`、`wip/` 之类用目录表达状态的机制。

## 影响

- 正面：agent 与人都从 `AGENTS.md` 一处进入；`DESIGN/API/DATABASE` 被拆入各自的家（`G1`/`A1`/`A6`/`A2`/`A3`/`A4`/`A5`）。
- 代价 / 后续动作：新建文档必须回填 §2 地图，否则"等于没写"；规范全文见 `M1`。
- 排期：本次文档整理（2026-10-15）生效。

## 未决项

- 文档体系根目录放在 `MyDISK/` 还是 git 仓库根 → 见 `S2`「待确认」第 1 条。
