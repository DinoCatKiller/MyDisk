# ADR-0001：技术栈定稿（Bun / Hono / oRPC / PostgreSQL / Redis / Drizzle）

|        |                                                                 |
| ------ | --------------------------------------------------------------- |
| ID     | `D1`                                                            |
| 类型   | 决策（**只增不改**）                                            |
| 状态   | 已接受                                                          |
| 更新   | 2026-10-15                                                      |
| 何时读 | 想质疑或更换技术栈（运行时 / 后端框架 / ORM / 数据库 / 队列）时 |
| 规模   | ~0.7k token                                                     |

## 背景

需要一个**单实例自托管**的私人云盘（`G1`）的技术栈：既要端到端类型安全（前后端共享一份接口类型），又要能直接读写流式二进制（`D3`），还要有可在线编辑的配置与后台任务（队列 / 邮件）。约束：不使用 Docker，服务由使用方自行拉起（`G1` §2）。

## 备选方案

| 方案      | 说明                                                                  | 优点                                                                                             | 缺点                                                             |
| --------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| A（选中） | Bun 1.3.14 + Hono 4 + oRPC 1.15 + Drizzle + PostgreSQL + Redis/BullMQ | 单一运行时跑通 dev/build/CLI；oRPC 端到端类型安全 + Zod 校验；Drizzle 纯 TS schema，贴合类型推导 | 生态较新，部分依赖为 RC/beta                                     |
| B         | Node + Express/Fastify + tRPC + Prisma                                | 生态成熟、文档多                                                                                 | Prisma 引擎重、schema 与 TS 类型有割裂；tRPC 无 OpenAPI 一等支持 |
| C（现状） | 保持 Better-T-Stack 脚手架默认（Bun + Hono + oRPC + Drizzle）         | 零改造                                                                                           | 脚手架自带公开注册与 AI 等内容，与本产品定位冲突（`D4`/`D5`）    |

## 决定

**采用 A（Bun + Hono + oRPC + Drizzle + PostgreSQL + Redis/BullMQ），版本基线以 `G1` §3 为准。**

**最关键的理由：oRPC 提供「一份路由定义 = RPC 调用 + REST 语义 + OpenAPI 文档」的端到端类型安全，正好同时满足前端类型安全（`A3`）、对外 REST（`D5`）与二进制面隔离（`D3`）三个需求。**

刻意收窄：**不引入** graphql、不引入除 BullMQ 外的任务框架、不为 ORM 另建类型层（直接用 Drizzle 推导）。

## 影响

- 正面：前后端共享 `AppRouter` 类型；Zod schema 直接转 JSON Schema；CLI / dev / build 同一运行时。
- 代价 / 后续动作：Solid 2 / Router / Nitro / TanStack Query 多为 RC/beta，需在 `package.json` `overrides` 锁定版本，并对关键用法先写最小验证页（风险见 `A1` §8）。
- 排期：P0 起生效。
