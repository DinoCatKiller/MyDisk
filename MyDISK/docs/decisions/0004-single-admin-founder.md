# ADR-0004：单管理员体系与 founder 唯一（禁公开注册）

|        |                                                  |
| ------ | ------------------------------------------------ |
| ID     | `D4`                                             |
| 类型   | 决策（**只增不改**）                             |
| 状态   | 已接受                                           |
| 更新   | 2026-10-15                                       |
| 何时读 | 改认证 / 管理员 / 注册流程，或想"顺便"开放注册时 |
| 规模   | ~0.6k token                                      |

## 背景

产品定位是**单用户 / 小团队自托管**（`G1`）：没有多租户，也没有面向公众的注册场景。但需要一个"超级管理员"与若干"普通管理员"的区分，且必须防止把唯一的最高权限账号误删 / 误降级。

## 备选方案

| 方案      | 说明                                                                                                               | 优点                             | 缺点                           |
| --------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------- | ------------------------------ |
| A（选中） | 关闭公开注册；`founder` 全局唯一（部分唯一索引）；`admin` 由 founder 创建、可被 founder 删；删除保护在服务层硬校验 | 契合自托管定位；最高权限不可失控 | 无自助注册，需 CLI / 后台建号  |
| B         | 保留公开注册 + 多角色                                                                                              | 通用                             | 与私人云盘定位冲突，徒增攻击面 |
| C         | 单管理员、无角色区分                                                                                               | 最简单                           | 无法表达"最高权限不可删"的约束 |

## 决定

**采用 A：`emailAndPassword.disableSignUp = true`，`/api/auth/*` 不对外暴露（全部封装为 oRPC `authRouter`）；`user.role ∈ {founder, admin}`，`founder` 用部分唯一索引全局唯一；删除 / 降级 founder 在服务层硬校验（不依赖前端）。**

**最关键的理由：私人云盘的"唯一最高权限账号"必须不可删除、不可降级，否则一次误操作即可锁死系统。**

刻意收窄：**不提供**公开注册、不提供 OAuth / 第三方登录；`admin` 之外的普通用户角色**不存在**。

## 影响

- 正面：权限模型简单可控；敏感操作可审计（`audit_log`）。
- 代价 / 后续动作：建号只能走 CLI（`A1` §5）或 founder 后台；首次登录 `must_change_password=true`。
- 排期：P1 已落地（`A3` §3）。
