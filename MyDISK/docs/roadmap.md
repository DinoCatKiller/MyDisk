## 排序原则

1. **地基先行（P0）**：契约（表结构 / 存储抽象）不稳，上层写多少返工多少。
2. **可跑优先（P1）**：先打通「安装 → 登录 → 进主界面」，让后续每个功能都有可挂载的壳。
3. **核心体验集中攻（P2）**：上传与文件管理是「像不像一个网盘」的判定线，且其难点（刷新续传）受浏览器限制，风险最高、最该早碰。
4. **外部依赖集中接入（P3）**：云存储驱动、同步、分享、压缩、预览都依赖外部队列与 SDK，放在有稳定外壳之后批量落地。
5. **收口增强（P4）**：WebDAV / 审计 / 找回密码 / 文档补全属「锦上添花」，放在核心可用之后。
